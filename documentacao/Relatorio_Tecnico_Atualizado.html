1. Objetivo e escopo

O programa recebe um arquivo Java por argumento e executa três análises: reconhece tokens, verifica a sintaxe e percorre uma árvore sintática abstrata (AST) para realizar verificações semânticas básicas. A implementação é manual, em C11, sem Lex/Flex nem bibliotecas externas de parsing.

A sublinguagem permite demonstrar declarações, atribuições, expressões, métodos, chamadas, condicionais e laços. Não há execução do programa Java, geração de bytecode nem conformidade integral com a especificação Java.

Esta versão descreve o código após a refatoração e a revisão crítica. O relatório antigo da raiz foi preservado como registro histórico.

2. Organização e análise léxica

ArquivoResponsabilidade
main.cLeitura, participantes, execução das etapas e saída.
lexer.c / lexer.hScanner manual, tokens, posição e erros léxicos.
parser.c / parser.hValidação sintática e construção da AST do subconjunto.
ast.c / ast.hNós, filhos, irmãos, impressão indentada e liberação.
semantic.c / semantic.hTipos, declarações, escopos, argumentos e retornos.
symbol_table.c / .hTabela hash de identificadores encontrados pelo lexer.

Fluxo: arquivo → tokens e tabela léxica → validação sintática → construção da AST → verificação semântica → resultado no terminal.

Erros léxicos impedem a análise sintática; erros sintáticos impedem a AST e a semântica. Uma construção aceita pela sintaxe mais ampla, mas não representada pela AST, pode produzir erro de subconjunto na etapa semântica.

Scanner e estruturas próprias

O scanner percorre os bytes do arquivo e reconhece identificadores, palavras-chave, números, textos, caracteres, booleanos, null, operadores e delimitadores. Espaços e comentários de linha/bloco são consumidos mantendo linha e coluna. Operadores são testados do mais longo ao mais curto.

Tokens e erros são guardados em vetores realocados conforme a necessidade. A tabela léxica utiliza 211 baldes e encadeamento por índices para colisões. Registra nome, primeira posição e número de ocorrências; não atribui tipos.

Escolha do parser

A descida recursiva foi mantida por relacionar procedimentos diretamente a classes, métodos e instruções. Expressões usam precedência e associatividade. O código permanece simples de acompanhar, sem geradores automáticos. A sintaxe reconhecida é maior que o núcleo semântico formalizado nas próximas páginas.

3. Gramática do núcleo — estrutura

Notação EBNF: colchetes indicam opção; chaves, repetição; barra vertical, alternativa. ID e LITERAL são fornecidos pelo lexer. O núcleo abaixo não é a gramática completa de Java nem de todas as extensões toleradas pelo parser.

programa = [ pacote ], { importacao }, { classe } ;
pacote = "package", ID, { ".", ID }, ";" ;
importacao = "import", [ "static" ], ID,
             { ".", ID }, [ ".", "*" ], ";" ;
classe = { modificador }, "class", ID, "{", { membro }, "}" ;
membro = ";" | { modificador }, tipo, ID, ( metodo | campo ) ;
metodo = "(", [ parametros ], ")", ( bloco | ";" ) ;
parametros = tipo, ID, { ",", tipo, ID } ;
campo = [ "=", expr ], { ",", ID, [ "=", expr ] }, ";" ;
tipo = tipoBase, { "[", "]" } ;
tipoBase = primitivo | "String" | ID ;
primitivo = "int" | "long" | "short" | "byte" | "float"
          | "double" | "boolean" | "char" | "void" ;
tipoLocal = ( primitivo | "String" ), { "[", "]" } ;
modificador = "public" | "private" | "protected" | "static"
            | "final" | "abstract" | "volatile" | "synchronized" ;

bloco = "{", { instrucao }, "}" ;
instrucao = bloco | declaracao | condicional | enquanto | para
          | retorno | expr, ";" | ";" | ( "break" | "continue" ), ";" ;
declaracao = tipoLocal, ID, [ "=", expr ],
             { ",", ID, [ "=", expr ] }, ";" ;
condicional = "if", "(", expr, ")", instrucao,
              [ "else", instrucao ] ;
enquanto = "while", "(", expr, ")", instrucao ;
para = "for", "(", [ inicio ], ";", [ expr ], ";",
       [ expr ], ")", instrucao ;
inicio = tipoLocal, ID, [ "=", expr ] | expr ;
retorno = "return", [ expr ], ";" ;

Restrições semânticas: void não é permitido para variáveis, campos ou parâmetros. Condições exigem boolean. Declarações locais nominais, listas de inicialização/atualização de for e outras extensões do parser não fazem parte do núcleo da AST. Blocos explícitos são recomendados nos exemplos.

4. Gramática do núcleo — expressões

expr = atribuicao ;
atribuicao = logicaOu, [ opAtrib, atribuicao ] ;
opAtrib = "=" | "+=" | "-=" | "*=" | "/=" ;
logicaOu = logicaE, { "||", logicaE } ;
logicaE = igualdade, { "&&", igualdade } ;
igualdade = relacional, { ( "==" | "!=" ), relacional } ;
relacional = soma, { ( "<" | ">" | "<=" | ">=" ), soma } ;
soma = produto, { ( "+" | "-" ), produto } ;
produto = unaria, { ( "*" | "/" | "%" ), unaria } ;
unaria = ( "!" | "+" | "-" | "++" | "--" ), unaria | posfixa ;
posfixa = primaria, { ".", ID | "(", [ argumentos ], ")"
                    | "[", expr, "]" | "++" | "--" } ;
primaria = LITERAL | ID | "this" | "(", expr, ")" | criacao ;
argumentos = expr, { ",", expr } ;
criacao = "new", tipoBase, ( "(", [ argumentos ], ")"
                           | "[", expr, "]" ) ;

Precedência e associatividade

Da menor para a maior: atribuições, ||, &&, igualdade, relações, soma/subtração, produto/divisão/resto e operadores unários/pós-fixos. Atribuições associam à direita; operadores binários restantes, à esquerda.

Restrições de expressões

  • O destino de atribuição/incremento precisa ser modificável; length de vetores é somente leitura.
  • Operações aritméticas exigem números, exceto concatenação com String. Expressões void não são valores utilizáveis nessas operações.
  • O núcleo demonstrado usa vetores unidimensionais. Índices e tamanhos aceitam int, short, byte ou char.
  • Chamadas resolvem métodos da classe corrente: nome simples, this.nome ou NomeDaClasse.nome. A distinção completa entre static e instância não é validada.
  • System.out.print recebe um argumento; println recebe zero ou um. Outras chamadas de membros externos não são resolvidas.
  • A sintaxe de new com objetos pode ser representada, mas assinaturas de construtores e existência de tipos nominais não são resolvidas integralmente.

5. AST e verificações semânticas

Cada nó guarda categoria, texto, tipo declarado quando aplicável, posição, primeiro filho e próximo irmão. O tipo inferido de acessos a vetores é guardado no próprio nó, separado do tipo declarado e liberado junto com a árvore.

Essa separação evita que a inferência de um operando sobrescreva o tipo de outro. A impressão continua exibindo as informações estruturais e os tipos declarados, sem incluir esse armazenamento auxiliar.

Declarações e escopos

A análise usa uma lista de símbolos com nome, tipo, categoria, nível de escopo e parâmetros de métodos. A busca de variáveis percorre a lista de trás para frente. Ao sair de um escopo, suas declarações são removidas.

Classes são analisadas em escopos isolados. Seus campos e assinaturas são registrados antes dos corpos dos métodos. Variáveis locais são analisadas em ordem, impedindo o uso de identificadores locais ainda não declarados.

Verificações realizadas

  • Existência de variáveis e redeclaração no mesmo escopo.
  • Visibilidade em blocos, métodos, laços e classes.
  • Tipos de inicializações, atribuições, operações e retornos.
  • Condições booleanas e operações lógicas.
  • Aridade e tipos de argumentos dos métodos resolvidos no subconjunto.
  • Uso de métodos como valores, void indevido e destinos não modificáveis.
  • Indexação de vetores, tipo dos índices/tamanhos e uso de length.

Promoção numérica e diagnósticos

Operações binárias priorizam double, float, long e int, nessa ordem. Operadores unários + e - promovem char, byte e short para int. Conversões especiais de constantes e atribuições compostas permanecem aproximadas.

Erros são listados por etapa, com linha, coluna e descrição. O percurso distingue uma instrução de uma lista; isso evita verificar novamente os irmãos de um nó, como condição e corpo de for.

7. Dificuldades e limitações

Problemas encontrados e corrigidos

A revisão identificou chamadas de erro incompatíveis no parser, funções excessivamente compactadas e mistura da construção da AST com a análise semântica. A refatoração separou as responsabilidades sem mudar os resultados dos casos da entrega anterior.

Novos testes revelaram tipos de elementos de vetores compartilhando um buffer, expressões de tamanho não percorridas, vazamento de símbolos entre classes, promoção incorreta de long e aceitação de void em expressões. Foram corrigidas também verificações de membros, chamadas da classe e length.

Proteção contra entradas muito profundas

Há limite de 128 níveis nas regras recursivas do parser e no percurso da AST. Não corresponde a 128 pares de parênteses: diferentes regras podem estar ativas simultaneamente. Quando excedido, é emitido diagnóstico. A impressão é limitada e a liberação da AST não usa recursão, inclusive para árvores profundas construídas a partir de longas sequências de operadores.

O que permanece fora do escopo

  • Herança, sobrecarga, generics completos, interfaces, exceções, lambdas, referências a métodos e resolução de bibliotecas externas.
  • Resolução completa de tipos nominais, assinaturas de construtores, visibilidade e distinção completa de static/instância.
  • Arrays multidimensionais e inicialização por listas { ... } no núcleo semântico, ainda que a sintaxe mais ampla reconheça algumas formas.
  • Inicialização definitiva de variáveis, análise completa de caminhos de retorno e validação de contexto de break/continue.
  • Todas as conversões numéricas de Java e suas regras de constantes.
  • Validação Unicode completa. O scanner aceita bytes não ASCII em identificadores, sem implementar as categorias Unicode da especificação.

O controle de redeclaração é por nível de escopo. A implementação didática permite alguns sombreamentos locais que Java rejeita; isso está preservado em um caso de regressão. A gramática e a semântica são deliberadamente parciais.
